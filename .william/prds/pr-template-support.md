# PR Template Support

## 1. Introduction/Overview

Add support for an optional PR body template that defines the structure/sections of the pull request description generated by `william pr`. The template is a markdown file whose content is injected into the AI prompt as extra context, guiding Claude to fill in the defined sections (e.g., `## Summary`, `## Test Plan`). The template path is configurable via `.william/config.json` and can be overridden per-run with a `--template` CLI flag.

## 2. Goals

- Allow users to define a consistent PR body structure across all workspaces in a project
- Make the template configurable in `.william/config.json` via a `prTemplate` key
- Add a `--template <path>` flag to `william pr` that overrides the config value for a single run
- Ask about template configuration during `william init`
- Fail fast with a clear error when a specified template file does not exist

## 3. User Stories

### US-001: Configure PR template in project config

**Description:** As a user, I want to set a `prTemplate` path in `.william/config.json` so that all `william pr` runs in this project use my preferred PR structure.

**Acceptance Criteria:**

- [ ] `ProjectConfig` type includes an optional `prTemplate` string field
- [ ] `loadProjectConfig` reads the `prTemplate` value when present
- [ ] When `prTemplate` is set and the file exists, its content is injected into the AI prompt
- [ ] When `prTemplate` is set but the file does not exist, `william pr` exits with error: `PR template not found: <path>`
- [ ] When `prTemplate` is not set, `william pr` behaves exactly as it does today (no template injected)
- [ ] Typecheck and lint pass

### US-002: Override template via CLI flag

**Description:** As a user, I want to pass `--template <path>` to `william pr` so that I can use a different template for a single run without changing my config.

**Acceptance Criteria:**

- [ ] `william pr <workspace> --template <path>` accepts an optional `--template` flag
- [ ] The CLI flag value takes precedence over the `prTemplate` config value
- [ ] If the flag points to a non-existent file, the command exits with error: `PR template not found: <path>`
- [ ] If neither the flag nor config provides a template, behavior is unchanged
- [ ] `--dry-run` output includes a line `Using PR template: <path>` when a template is active
- [ ] Typecheck and lint pass

### US-003: Inject template into AI prompt

**Description:** As a developer, I want the PR template content appended to the existing `pr-description-instructions.md` prompt so that Claude uses the template sections when generating the PR body.

**Acceptance Criteria:**

- [ ] The `generatePrDescription` function accepts an optional template string parameter
- [ ] When provided, the template content is injected into the prompt as a new `{{pr_template}}` section
- [ ] The `pr-description-instructions.md` template includes a `{{pr_template}}` placeholder with surrounding instructions telling Claude to follow the provided structure
- [ ] When no template is provided, the `{{pr_template}}` placeholder is replaced with an empty string (or removed), preserving current behavior
- [ ] Typecheck and lint pass

### US-004: Ask about PR template during init

**Description:** As a user running `william init`, I want to be asked whether I want to configure a PR template so that I can set it up during project initialization.

**Acceptance Criteria:**

- [ ] During `william init`, after the existing prompts, a confirm prompt asks: "Do you want to configure a PR template?" with default `No`
- [ ] If the user answers Yes, an input prompt asks for the template file path with default `.william/pr-template.md`
- [ ] The provided path is saved as `prTemplate` in the generated `config.json`
- [ ] If the user answers No, no `prTemplate` key is added to `config.json`
- [ ] Typecheck and lint pass

## 4. Functional Requirements

- **FR-1:** The `ProjectConfig` interface must include an optional `prTemplate?: string` field representing a relative file path to the PR body template.
- **FR-2:** The `PrOptions` interface must include an optional `template?: string` field.
- **FR-3:** The `william pr` CLI command must accept an optional `--template <path>` option.
- **FR-4:** Template resolution order: CLI `--template` flag > `config.prTemplate` value > no template.
- **FR-5:** When a template path is resolved, the system must verify the file exists. If it does not, exit with error message `PR template not found: <resolved-path>` (exit code 1).
- **FR-6:** When a template file is found, read its content and pass it to `generatePrDescription`.
- **FR-7:** `generatePrDescription` must accept an optional `template` parameter and inject it into the prompt via a `{{pr_template}}` placeholder in `pr-description-instructions.md`.
- **FR-8:** The `pr-description-instructions.md` template must include a conditional section for the PR template that instructs Claude to use the provided structure for the body when present.
- **FR-9:** When `--dry-run` is active and a template is in use, print `Using PR template: <path>` before the title/body output.
- **FR-10:** During `william init`, prompt the user with a confirm question "Do you want to configure a PR template?" (default: No). If yes, ask for the file path (default: `.william/pr-template.md`) and persist as `prTemplate` in `config.json`.

## 5. Non-Goals (Out of Scope)

- No auto-creation of a starter template file — if the file doesn't exist, that's the user's responsibility
- No support for multiple templates per project or per-workspace templates
- No changes to the revision PR flow — this only affects `william pr`
- No validation of template content (any markdown is accepted)
- No migration of existing configs — `prTemplate` is a new optional field with no legacy equivalent

## 6. Edge Cases & Error Handling

- **Template file missing (CLI flag):** Exit with error `PR template not found: <path>` before any git operations or AI calls.
- **Template file missing (config value):** Same behavior — exit with clear error.
- **Template file is empty:** Treat as no template (inject empty string). No error.
- **Template file is very large:** No explicit size limit. The AI prompt already truncates diffs at 100KB; the template is expected to be small (a few hundred bytes). No guard needed.
- **Both CLI flag and config set:** CLI flag wins. Config value is ignored for that run.
- **Config has `prTemplate` but value is empty string:** Treat as no template configured.
- **Init with existing config that already has `prTemplate`:** The existing overwrite-confirmation flow handles this — the entire config is rewritten.

## 7. Technical Considerations

- The `pr-description-instructions.md` template (in `templates/`) needs a new `{{pr_template}}` placeholder. The `generatePrDescription` function in `src/pr.ts` already does string replacements on this template — add one more `.replace()` call.
- The `prCommand` function needs to load the project config via `loadProjectConfig` to read `prTemplate`. Currently it doesn't load config — it will need to.
- Template paths in config should be resolved relative to the project root (where `.william/` lives), consistent with how `prdOutput` works.
- The `loadProjectConfig` call in `prCommand` needs the project root directory. This can be derived from `state.targetDir` which points to the project root.

## 8. Success Metrics

- All existing `william pr` tests continue to pass (no regressions)
- `william pr` with no template configured produces identical output to current behavior
- `william pr --template <path>` injects the template content into the AI prompt
- `william init` correctly persists `prTemplate` when the user opts in
- Typecheck and lint pass with zero errors
